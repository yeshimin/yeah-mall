一套内容规范，组合不同后台外壳

运营账本与轻白工作台不再被拆成两套页面。筛选、表格、详情、弹窗和状态表达保持唯一实现，只把导航位置、导航主题、信息密度和折叠状态作为独立配置。这样既能满足不同使用偏好，也能把 YeahBoot 上游合并冲突集中在布局组件内。

与 YeahBoot 的实现边界

越靠左越适合直接在本项目实施，越靠右越需要谨慎评估上游合并成本。

设计令牌直接实施

颜色、字号、间距、圆角、状态色集中到商城主题变量。上游合并后重新挂载主题即可。

商城业务组件深度优化

筛选栏、商城表格、详情抽屉、审核弹窗由 YeahMall 自己维护，不侵入 YeahBoot 通用组件。

YeahBoot 通用页面轻量覆盖

系统管理等页面优先只调整主题变量和外层间距，避免重写 DOM、事件与权限结构。

后台整体导航谨慎选择

侧栏宽度和颜色可低成本调整；双栏导航或顶部主导航会提高以后合并上游的成本。
